# 家庭遍历与开关设备支持

## 背景

eWeLink 的设备列表按家庭组织，部分设备使用标量 `params.switch` 表示状态，另一些设备则使用 `params.switches[]`。项目已实现跨家庭查询，并在不改变公开 REST 模型的前提下兼容这两种格式。

## 家庭与设备列表

每次调用设备列表接口时，客户端都会：

1. 请求账号下的全部家庭。
2. 对每个家庭分别请求设备，并独立处理分页。
3. 解析受支持的开关设备。
4. 按 `device_id` 去重，并保持首次出现的顺序。

重复家庭 ID 只会查询一次。家庭响应无效、任一家庭查询失败或分页游标异常时，整个请求失败，不返回可能产生误导的部分结果。家庭 ID 和设备信息不会持久化或缓存。

## 支持的开关格式

设备满足以下任一种格式时被视为受支持：

- `params.switch` 的值为 `on` 或 `off`。
- `params.switches` 包含唯一的 `outlet: 0`，且它的 `switch` 为 `on` 或 `off`。

数组中的其他 outlet 会被忽略。`outlet: 0` 缺失、重复、状态非法或字段格式异常时，该设备不受支持。如果同一设备同时提供有效的标量和数组格式，优先使用标量格式，以保持早期设备的兼容行为。

公开 API 始终将设备表示为单个 `on|off` 开关，不暴露 outlet 参数。

## 指定设备读取

读取指定设备时，客户端会尝试匹配自有设备和共享设备，并保留云端返回的实际 `itemType`。找到设备后再解析开关格式：

- 没有找到设备时返回设备不存在错误。
- 找到设备但没有受支持的开关格式时返回设备不受支持错误。
- 在线状态和开关状态来自当前云端响应，不使用缓存。

## 设置设备状态

设置接口只接受 `on` 和 `off`，无效输入会在发起任何云端请求前被拒绝。有效请求按以下顺序执行：

1. 实时读取设备元数据。
2. 确定设备的实际 `itemType` 和开关格式。
3. 标量设备发送 `{"switch":"on|off"}`。
4. 数组设备发送 `{"switches":[{"outlet":0,"switch":"on|off"}]}`。

写入成功后不会再次查询状态。成功响应表示 eWeLink 已接受并处理该命令；调用方需要确认最终状态时可显式调用状态接口。

如果读取或写入阶段遇到 Token 错误，Gateway 会刷新 Token，并从整个设置操作的开头最多重试一次。这保证重试仍会基于最新设备元数据构造请求。

## 安全与验证

- 不记录家庭响应、设备原始响应、Token、App Secret 或控制请求中的敏感内容。
- 不提交真实家庭 ID、设备 ID、设备名称或凭据。
- 自动化测试覆盖多家庭分页、去重、无家庭、异常响应、标量格式、数组 outlet 0、自有/共享设备、正确写入格式以及 Token 重试。
- 真实设备的只读查询可用于验收；实际开关操作应由操作者明确指定设备后执行。
